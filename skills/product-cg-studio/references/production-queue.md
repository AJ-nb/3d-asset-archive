# 从多条产品简报开始

选择与来件接近的示例。只有想法或一张草图时，使用[折叠阅读灯概念工单](../examples/concept/products.json)，把清单和引用的草图放在同一输入目录。交付要求已经明确时，可以复制[两款原创产品的制作清单](../examples/products.json)。同一批可以混合概念、从零制作和接手修改三类工单。

在技能目录运行以下命令，替换清单路径和输出目录。只需 Python 3 标准库。

```sh
python scripts/prepare_queue.py examples/products.json --out work/orders-01
python scripts/prepare_queue.py examples/concept/products.json --out work/concept-01
```

每个合格产品生成一份 `<id>/brief.md`。`queue-report.json` 的 `ready` 表示工单文件已生成，接下来做什么看该行的 `next_step`。`failed` 行附有输入行号和原因。脚本在本地准备材料，访谈、查找参考和制作由使用本技能的 AI 执行。

### 如何填写一行

| 字段 | 填法 |
| --- | --- |
| `id`、`mode` | 独立产品 ID 使用小写字母、数字、短横线和下划线，首位为字母或数字。构想仍待设计用 `concept`，按明确的描述或实物参考起模用 `create`，接手已有模型或场景用 `revise`。 |
| `brief` | 概念项目可以原样写客户的一句话，未定的结构、材质或用途留给访谈。已有明确要求时，写清型号或原创设计、重点部件、已有问题和使用场景。 |
| `references`、`source` | `references` 可省略或为空。引用文件写成相对清单所在目录的路径，使用 `/`。接手模式另填 `source` 指向实际存在的源工程；脚本验证路径和文件存在性，格式能否导入需要在制作时试开。 |
| `resolution`、`deliverables`、`acceptance` | 分别为 `[宽, 高]` 像素、交付物文本数组和验收条件文本数组。概念行可省略任一未知字段，其他模式沿用已有要求。视频写时长与帧率，多个版位写各自画幅。“侧光下能看清旋钮刻度”是可复验的验收条件。 |
| `question_overrides` | 可选，用于 `concept` 或 `create`。用题号字符串映射到针对本案的一句话问题。例如 `{"6": "人物抓住伞柄时，哪只手和哪段手指必须贴住它？"}` 会替换默认的连接与接触题。题号与[访谈题库](concept-intake.md)一致。 |
| `review` | 可选的非空文本数组。逐项写出本款最容易出错的部件、尺寸依据或姿态，例如“俯视侧棱应与图纸 R1 对齐”“展开到限位时线束仍有余量”。省略此项也会生成模型复核与重渲步骤。 |

接手已有计时器工程时，将该行的 `mode` 改成 `"revise"`，加入 `"source": "timer/original.blend"`，将实拍资料写成 `"references": ["timer/front.jpg", "timer/side.jpg"]`。这些是路径写法示例，运行前换成自己的文件。重复 ID 的所有行一起报错，以免任意选中一个版本。

### 根据来件进入对应环节

| 报告中的下一步 | 工单用法 |
| --- | --- |
| `concept_intake` | 原创设计尚在构思中。目录里另有 `client-interview.md` 客户访谈稿及 `design-decisions.md` 参考选择与决定记录。可以只写 `id`、`mode`、`brief` 开始。 |
| `inspect_inputs` | 已有的 `create` 清单只有文字或图像等资料，或作者提供了自定义访谈题。目录里备有两份访谈文件。AI 读简报、打开图像后判断是待设计的概念，还是规格已定的复现。如果是概念，走下一段的访谈与找样流程。 |
| `production` | 按工单起模或接手工程。`create` 引用可识别的三维几何文件时默认进入此环节。几何仅供启发、客户仍需确定设计方向时，用 `concept` 明确指定。 |

概念工单先把客户说过的话和草图标注读一遍。把访谈稿改成与这款对象直接相关、客户能回答的 **至少 10 个独立问题**。已给出答案的问题换成影响设计的下一层问题，按情况询问看不见的背面、运动、支撑、尺寸锚点或成片用途。在当前对话向客户实际提问，可按主题分批；代客户经理准备交接稿时，使用生成的访谈文件。

用已知线索同步查找同类产品和可借鉴的其他对象，核对原始页面，再按[参考研究方法](design-precedents.md)向客户展示有编号的案例。请客户用案例编号指出保留、避开、组合或委托设计的具体部分。[阅读灯参考板](../examples/concept/lighting-references.md)演示了如何把外形灵感、支撑问题与布光用途对应起来。将选择、理由、未定项及依据记入 `design-decisions.md`，回填 `brief.md` 的设计、交付物和验收条件。以客户已选或明确委托的范围出白模，优先验证最有影响的未知项。

### 让 AI 逐单完成制作

1. 读取报告，逐项打开 `ready` 工单。在各自产品目录内工作，原始参考与源工程保留在输入目录。采用接手模式时，先重开源工程检查贴图、链接资产与上次交付状态，再保存工作副本。
2. 根据工单走建模或修复路径。复制[模型复核表](model-review.md)里的部件、连接、尺寸与返工记录，在每款目录里保存该款的证据。对照其验收条件精修，在同一基准复验后再输出可重开的 `.blend`、命名场景和相机。某项输入不足以验证实物尺寸时记录限制，其他产品照常推进。
3. 把已准备好的镜头汇总给批量渲染入口。交付时按每项工单复核工程、画幅、数量与成片，单独列出受阻项。

输出目录必须是新路径。修复缺件后，可把失败项单独组成新清单，再指定新的 `--out`。进程退出码 `0` 表示全部工单准备完成，`1` 表示有产品失败，`2` 表示清单或输出目录本身有误。客户已填写的访谈稿、参考选择和简报在原工单目录里继续维护。
