# 从多条产品简报开始

把 [示例工单清单](../examples/products.json) 复制到本批项目的输入目录。示例中的两款原创产品仅依赖文字，能直接演练。每行产品写清要做什么、源文件、交付物、像素画幅和看得见的验收条件。视频的时长和帧率写在交付物里；有多种画幅时列明每张图或每个视频的例外尺寸。

在技能目录运行以下命令，替换清单路径和输出目录。只需 Python 3 标准库。

```sh
python scripts/prepare_queue.py examples/products.json --out work/orders-01
```

每个合格产品生成一份 `<id>/brief.md`。`queue-report.json` 的 `ready` 表示工单可开始制作，`failed` 含对应行号和具体原因。准备脚本只生成工单。后续由 AI 带着技能执行建模、精修和渲染。

### 如何填写一行

| 字段 | 填法 |
| --- | --- |
| `id`、`mode` | 独立产品 ID 使用小写字母、数字、短横线和下划线，首位为字母或数字。纯文字、照片或图纸起模用 `create`；继续修改已有模型或场景用 `revise`。 |
| `brief` | 写明型号或原创设计、造型与材质、重点部件、已有问题和使用场景。 |
| `references`、`source` | `references` 可省略或为空。引用文件写成相对清单所在目录的路径，使用 `/`。接手模式另填 `source` 指向实际存在的源工程；脚本验证路径和文件存在性，格式能否导入需要在制作时试开。 |
| `resolution`、`deliverables`、`acceptance` | 分别为 `[宽, 高]` 像素、交付物文本数组和验收条件文本数组。写“侧光下能看清旋钮刻度”比写“更高级”更容易复验。 |

接手已有计时器工程时，将该行的 `mode` 改成 `"revise"`，加入 `"source": "timer/original.blend"`，将实拍资料写成 `"references": ["timer/front.jpg", "timer/side.jpg"]`。这些是路径写法示例，运行前换成自己的文件。重复 ID 的所有行一起报错，以免任意选中一个版本。

### 让 AI 逐单完成

1. 读取报告，逐项打开 `ready` 工单。在各自产品目录内工作，原始参考与源工程保留在输入目录。采用接手模式时，先重开源工程检查贴图、链接资产与上次交付状态，再保存工作副本。
2. 根据工单走建模或修复路径。每个产品先出低成本预览，对照其验收条件修正，再保存可重开的 `.blend`、命名场景和相机。某项输入不足以验证实物尺寸时记录限制，其他产品照常推进。
3. 把已准备好的镜头汇总给批量渲染入口。交付时按每项工单复核工程、画幅、数量与成片，单独列出受阻项。

输出目录必须是新路径。修复缺件后，可把失败项单独组成新清单，再指定新的 `--out`。进程退出码 `0` 表示全部工单可制作，`1` 表示有产品失败，`2` 表示清单或输出目录本身有误。
